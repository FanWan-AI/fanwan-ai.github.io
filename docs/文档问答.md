太好了，走到“论文问答”这步，差一点就能做出非常好用的 Paper QA 了。下面我给你一份“能直接照着干”的落地方案：先把你现有前端改成一个**本地（浏览器内）RAG**，可选再叠加一个超轻的 Cloudflare Worker 做远程 PDF 预处理。整个方案不需要付费 API，也尽量不引入复杂后端。

# 总体思路（先给你结论）

* **解析**：用 `pdf.js` 在浏览器里把 PDF 抽文本 + 坐标（为双栏处理做准备）。
* **清洗与分栏**：基于行的 `x` 坐标做两栏聚类/分桶，去页眉页脚、参考文献段落标记。
* **切块（chunking）**：按版面与语义切块（段落/标题/小节），生成稳定锚点（页码+段号）。
* **向量化**：用浏览器内的 `Transformers.js`（ONNX Runtime Web）加载一个**轻量免费**英文句向量模型（如 `all-MiniLM-L6-v2`）生成向量，存 `IndexedDB`。
* **检索**：余弦相似度 Top-k + **轻量重排**（BGE reranker 或简单 BM25 互补），按块把最相关上下文拼入 LLM 提示。
* **引用与高亮**：把每段上下文附带 `(Page X, Sec Y)` 锚点。答案里自动插入 `[pX §Y]`，前端消息气泡可点击回跳原 PDF 页面位置。
* **与你现有 UI 对接**：你代码里已经有“RAG 模式”的开关与 payload 字段占位；我们把“真的检索出的上下文”在发送给模型前塞进 `messages` 即可（见下面补丁）。

> 你现在的 `zhida.js` 里 `RAG` 还只是个占位：切到 rag 会弹 “文档问答即将上线”的提示（`notify(t('ai_qa_docs_coming_soon'), 'warning')`），`buildPayload()` 虽然写了 `payload.mode = 'rag'`，但并没有真正做检索与拼接上下文（见这里的逻辑：在发送前只是 `messages = 系统 + 历史对话`，没有把文档嵌入的结果插进去）。

## 一步一步实现（纯前端 MVP，约 2～4 小时）

### 0）准备依赖

在 `lab/tools/ai_zhida/` 下新建 `rag/` 目录，放三个模块：

* `pdf-loader.js`：基于 `pdf.js` 的抽取。
* `embedder.js`：基于 `@xenova/transformers`（Transformers.js）做向量。
* `vector-store.js`：很薄的一层，做向量的存取（`IndexedDB`）和 Top-k 近邻。

在 `ai-zhida.html` 里按需引入（或在 `zhida.js` 顶部动态导入）。

### 1）PDF 解析与双栏处理（pdf-loader.js）

* 用 `pdfjs-dist` 的 `getPage(i).getTextContent({ normalizeWhitespace:true, includeMarkedContent:true })` 拿到每行的 `item.transform` 与 `width`。
* **两栏检测**：统计同一页所有行的 `x` 中值，做 2 类 k-means（或简单“阈值切两堆”），再按 `(y desc, x asc)` 排序重组段落。
* 去页眉/脚注：每页 y 最上/最下 5–7% 的行大概率是页眉脚，匹配“arXiv”、“Proceedings”、“Page \d+”等噪声正则剔除。
* 结果输出成结构化块：`{ page, x0, y0, text, sectionHint }`，遇到大字号/粗体/居中行做“标题提示”。

### 2）切块（chunking）

* **规则**：按段落 + 标题边界切块；每块 600–1200 字符（英文）或 100–200 token 左右；相邻块滑窗 10–15% 重叠，保证连续性。
* 给每块赋 ID（如 `p{page}-c{idx}`）与 **可回跳锚点**（页码、块内偏移）。

### 3）本地嵌入（embedder.js）

* 使用免费模型 `all-MiniLM-L6-v2`（句向量，速度快，英文学术文本够用）。

  * 代码要点：

    ```js
    import { pipeline } from '@xenova/transformers';
    const embed = await pipeline('feature-extraction', 'Xenova/all-MiniLM-L6-v2', { quantized: true });
    const vec = await embed(chunk_text, { pooling: 'mean', normalize: true });
    // vec.data 是 Float32Array
    ```
* 初次载入模型耗时 ~2–6 秒（取决网络，缓存后很快）。你也可以在设置面板里做“预热模型”按钮。

### 4）向量库 & Top-k（vector-store.js）

* 把每块的向量 + 元数据放进 `IndexedDB`（key：文档指纹+块 ID）。
* 检索时：对 query 做一次嵌入，暴力余弦 Top-k（在 JS 里 10k 块以内够快），或引 `hnswlib-wasm` 做近似检索（大 PDF 集合时再上）。
* **轻量重排**：先 BM25（只对 Top-k 的原文做）+ 余弦分数线性融合，或引 `bge-reranker-base`（会稍重），建议先不引。

### 5）把上下文塞进你现有对话流（zhida.js 小补丁）

* 你现在的 `handleSend()` 会在用户发问后构造 `payload = buildPayload()` 并直接流式请求（SSE）。
  我们在**构造 payload 之前**插入一步：如果 `state.mode === 'rag'`，则：

  1. 调 `rag.search(query, topK=6, maxChars≈1600)` 得到若干块 `ctx[i]`；
  2. 生成一个 system 或者第一条 assistant 工程提示，形如：

     ```
     你是科研论文助手。仅依据给定上下文回答，给出清晰的要点，并在句尾用 [pX §Y] 标注来源。
     如果上下文不足以回答，请说“资料不足”，并提示我定位到相关小节。
     ```
  3. 把拼好的 `CONTEXT`（合并若干块，并保留块内锚点）作为 **额外一条 system** 或 **第一条 user 前面的 'context' 块**。示例：

     ```js
     messages.unshift({
       role: 'system',
       content: `CONTEXT:\n${ctx.map((c,i)=>`[${i+1}] (p${c.page} §${c.sec}) ${c.text}`).join('\n\n')}`
     });
     ```
* 这样就不改你的代理/模型，只在前端把命中的内容喂给 LLM，即刻提升“对文献细节的把握”。

> 你现有代码里 `buildPayload()` 仅把系统提示 + 对话历史塞进 `messages`；我们要在它**之前**改造内存 `state.messages`，或在 `buildPayload()` 内判断 `state.mode==='rag'` 时把 `CONTEXT` 追加进去（推荐在 `buildPayload()` 里做，结构更清晰）。

## 质量飞跃的 6 条“论文场景”增强（建议按序加）

1. **分栏鲁棒性**

   * 两栏之外，注意“图表宽行”会跨两栏，遇到宽行就单独成块，不要拼进左/右栏段落。
   * 公式行识别：正则匹配常见数学符号密度，公式块单独存，不参与 BM25，但可参与关键词召回。

2. **章节与结构化检索**

   * 解析 “Abstract/Introduction/Method/Results/Conclusion/References” 标题行，给每块打 `section` 标签。
   * 查询时优先抽 `Abstract` + 匹配 `section` 的块（例如问“结论是什么”，让打分对 Conclusion 加 0.15 bias）。

3. **图表与表格**

   * 纯文本难以覆盖图表。先做**图题（Figure/Table caption）单独切块**，并对“本段文本上方最近的 caption”建立指针。
   * 真要 OCR：引 `tesseract.js` 仅对“疑似图内文字”的区域做按需 OCR（点击“展开图表文字”再跑，避免全量卡顿）。

4. **引用可点击回跳原文**

   * 在答案里出现 `[p3 §12]` 时，把它渲染成链接，点击时在右侧打开“PDF 预览抽屉”，定位到第 3 页并高亮该块矩形区域。

5. **多文献同时问答**

   * `docId` 维度组织向量，检索时先做“跨文献 Top-m”，再在每篇内取前 n 段，合并后重排，答案里注明 `[Paper A p3 §5]`。

6. **长问题/思维链**

   * 对“综述型问题”（比如“这两篇方法的差异和优缺点”），先让前端把用户问句改写成**多个子查询**（问题拆解），对子查询各自检索，再拼上下文。

## 和 arXiv“论文中心”的对接

* arXiv 元数据：免费 `http://export.arxiv.org/api/query?search_query=...`（Atom）。取 `id`, `title`, `authors`, `pdf_url`。
* PDF 获取：直接 `https://arxiv.org/pdf/<id>.pdf`。
* 前端支持两种入口：

  1. **输入 arXiv 链接/ID**：自动抓 PDF、解析、建索引。
  2. **从你的“论文中心”列表点击“问答”**：传入 `pdf_url` 和 `paper meta`，前端开始解析与缓存。
* 大文件/跨域偶发失败：可选用一个超轻 **Cloudflare Worker“中转 + 缓存”**（仅透传公开 PDF，附 `Cache-Control`），减少 CORS 与 429。

## 需要改的几行代码（关键点）

1. **允许更大 PDF**（很多论文 10MB 以上）
   在 `zhida.js` 顶部把 `MAX_FILE_SIZE` 从 `10 * 1024 * 1024` 提到 `30 * 1024 * 1024`（或做成设置项）。

2. **真正启用 RAG**

   * 在 `handleModeChange()` 里，目前切到 rag 会 `notify('即将上线')`。你可以保留提示，但别早退；最关键是在 `buildPayload()` 里：

     * `if(state.mode==='rag'){ const ctx = await rag.search(...); messages.unshift({role:'system', content:'CONTEXT: ...'}) }`。
   * 并在 `handleSend()` 里把 `buildPayload()` 变为 **异步**（先跑检索再发 SSE）。

3. **设置项**

   * 在设置面板加一个“本地嵌入模型预热/下载”与“清空索引”按钮，状态写入你现有的 `STORAGE.SETTINGS`（你已经有本地化持久化逻辑，可复用）。

## 现实可行的免费模型建议（浏览器内运行）

* **句向量**：`all-MiniLM-L6-v2`（英文论文非常够用；Transformers.js 有量化版）。
* **重排（可选）**：`bge-reranker-base`（12 层，能跑但会慢，建议作为“质量模式”开关）。
* **关键词互补**：加一个超轻 BM25（纯 JS 实现，很快）。

> 中文论文或中英混排时，可换 `multilingual-MiniLM-L12-v2`；不过针对英文论文，MiniLM 英文版效果通常更稳。

# 你可以直接照做的最小改动顺序（超短清单）

1. `npm i pdfjs-dist @xenova/transformers idb`（或用原生 IndexedDB）。
2. 新建 `rag/pdf-loader.js`、`rag/embedder.js`、`rag/vector-store.js`，按上面流程实现 200~300 行 MVP。
3. 在 `zhida.js`：

   * `buildPayload()` 里判断 `state.mode==='rag'` 时先 `await rag.search()`，然后把 `CONTEXT` 以一条 `system` 消息 `unshift` 进 `messages`。
   * `handleSend()` 改为 `await buildPayload()`（异步）。
4. 设置面板里加“预热模型/清空索引”按钮（复用你已有的本地存储）。
5. 在“论文中心”卡片加一个“问答”按钮，传 `pdf_url`，前端拉 PDF 并入库后自动跳到 rag 模式。

这样上线后，你立刻就能：把 arXiv 推荐的论文一键拉到网页里，让 LLM 在**本地检索到的真实上下文**基础上回答，并且答案都带有可点击的页码/段落引用。体验会比“把整篇 PDF 扔给 LLM 让它自己读”稳得多、可控很多。
