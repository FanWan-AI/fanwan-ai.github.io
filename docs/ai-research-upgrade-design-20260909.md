# AI 论文中心与模型雷达升级设计

## 范围与依据

基于 [当前审计](ai-research-modules-audit-20260909.md)，升级两套现有模块，不另建站点、不增加新的顶层栏目。用户已确认之前 DeepSeek 调用失败源于欠费并已处理；这解释了调用故障，但不能为故障后发布原始信息流的逻辑免责。

本文件是维护文档，不向网站读者展示内部生成规范。

## 产品边界

| 模块 | 核心问题 | 读者得到什么 |
| --- | --- | --- |
| AI 论文中心 | 这篇研究改变了什么，我能借鉴什么？ | 可信论文身份、完整中文解读、实验依据与边界、下一步可尝试的实验、原始来源 |
| AI 模型雷达 | 这个模型/工具能解决什么，值不值得试？ | 有信息量的中文介绍、适用任务、当前关注理由、一手文档和已知限制 |

保留日期归档、分类库、经典演进轨迹及原有链接。页面采用现有视觉体系，卡片重点是内容而非热度数字。历史资料不等于新审阅结果；旧日期必须真实保留。

## 共同发布契约

1. 生成失败、认证/余额错误、JSON 损坏或关键字段不合格时，任务失败；上一份有效公开版本不被原始信息流或占位卡覆盖。
2. 先获取来源，再生成解读，验证全部待发布文件后再写入。禁止英文复制到中文字段、字符数截断冒充摘要、默认影响力/复现性打分。
3. 数字、能力、限制和链接都应能回溯来源。只有摘要时明确证据范围；建议实验不能包装成已复现结果。许可、显存等未知信息不推测。
4. 论文精选仅接收有一手论文身份的研究。讨论帖和教程不作为论文入选。模型热度不能绕过正文质量要求。
5. 精选数量是上限而非配额。重复模型/量化版本不能挤占多个精选位；旧项目有实质更新仍可被选中。
6. 所有动态文本安全渲染；来源链接限制为合法公共 HTTPS/HTTP 地址，不执行外部 HTML。

## 更新、成本与性能

- 目标调度：论文每天北京时间 08:00，模型雷达每天 10:30；实际完成时间受 Actions 排队与来源服务影响。
- 控制候选数量、请求并发、超时、重试和输出长度；失败不无限重试，不全库重新付费生成。
- 首屏只读当前版与轻量日期索引；历史数据按需加载。读者看见当前展示的实际日期，而不是默认今天。
- 保持现有 GitHub Pages 静态部署：LLM 密钥仅在受控生成端使用，不进入浏览器文件。

## 并行实施与验收

论文工作包负责其页面、生成器、工作流及专属测试；模型工作包负责其页面、三阶段链路、质量规则及专属测试。总集成负责共享命令、交叉检查、真实运行、浏览器和部署验收，保护其他代理的创业模块改动。

最低验收：

- 离线测试覆盖正常发布、空中文、英文冒充中文、截断、来源身份错误、重复项目、失败后旧文件不变。
- 有额度限制的真实调用，人工检查生成结果与一手来源对应，而不只检查 JSON 可解析。
- 浏览器检查中文/语言切换、卡片与详情、日期和搜索、桌面/移动端溢出与键盘操作。
- 提交范围无密钥、无临时文件、无无关创业模块变动。
- 一次端到端运行不能证明长期稳定；后续定时运行需继续依据实际结果评估。

## 已核查的一手接口约束

- [arXiv API 手册](https://info.arxiv.org/help/api/user-manual.html)：通过查询获取结构化论文身份与摘要；限制请求数量、保留原始来源，不将新闻源混入论文身份池。
- [Hugging Face API](https://huggingface.co/docs/hub/api) 与 [客户端字段说明](https://huggingface.co/docs/huggingface_hub/package_reference/hf_api)：`downloads` 与 `downloadsAllTime` 是不同字段，`cardData` 提供模型卡元数据。
- [HF 下载计数说明](https://huggingface.co/docs/hub/models-download-stats)：计数依赖特定文件请求，可包含 GET/HEAD；不等价于独立用户，GGUF 仓库整体下载存在重复计数可能。页面不能把下载热度解读为实际能力或客户规模。

以上仅用于实现接口与展示语义，不为具体模型能力背书。
