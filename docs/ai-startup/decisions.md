# 决策记录

## ADR-001：静态站点 + Actions 后端

**决定**：不增加常驻服务器。采集、DeepSeek 调用、校验和发布全部在 GitHub Actions 中完成，浏览器只读取静态 JSON。

**原因**：与现有 GitHub Pages 架构一致，成本低，密钥不下发客户端，数据可由 Git 审计和回滚。

## ADR-002：质量优先于“十大”配额

**决定**：每日上限为 10 条，不保证恰好 10 条；阈值不足的候选被丢弃。

**原因**：强行凑数与用户明确要求的低噪声、高营养目标冲突。

## ADR-003：日报自动发布，案例审阅后发布

**决定**：结构化短内容在双重门禁后可自动发布；长篇案例默认生成草稿并经 promote 发布。

**原因**：长文的论证质量、叙事重复和隐含因果更难用单次模型调用可靠判断。

## ADR-004：一个页面、两个 URL 状态

**决定**：使用一个页面与 hash/query 状态承载日报、案例索引和案例详情。

**原因**：减少静态页面重复，保持快速切换，同时让案例链接可分享。

## ADR-005：退休模块不删除历史文件

**决定**：从 AI 工坊和部署入口移除 AI 理财助手、AI 每日学堂、AI 游戏中心，但保留仓库历史文件。

**原因**：满足“不显示、不挂载”，同时保留可恢复性并降低破坏性操作风险。

## ADR-006：story_type 数据层统一英文枚举

**决定**（2026-09-04，P1）：案例 `story_type` 合法值仅为 `growth | pivotal_decision | failure | business_model | technical_commercialization | comparison`，由 case-detail 与 cases-index 两份 JSON Schema 枚举强制；生成端 prompt schema 同步约束；前端负责三语标签映射，未知值原样展示。存量中文值一次性迁移。

**原因**：前任种子数据使用中文（“技术商业化”）而流水线枚举为英文，schema 未校验导致两种取值并存；枚举收口让门禁可测，展示语言回归前端职责。

## ADR-007：提交策略为精确路径白名单

**决定**（2026-09-04，P1 起）：本模块任何提交只 `git add` 蓝图 §4 P4 列出的白名单路径；工作区中的退休模块改动、ModelSwatch 临时数据与未知改动由总验收逐一 diff 审计后单独处理，永不与本模块混提。

**原因**：工作区混有大量无关未跟踪数据与跨模块修改，`git add -A` 会把临时数据与未审计改动一并发布到 GitHub Pages。
